# MeetFlow

> 여러 회의를 하나로 이어서 프로젝트 전체의 흐름을 계속 붙잡아주는 AI

**🔗 [데모 바로가기](https://suming030.github.io/meetflow/)** — 구글 계정으로 로그인하면 바로 써볼 수 있습니다.

공모전·팀플·동아리를 운영하는 대학생 팀을 위한 서비스입니다.
기존 AI 회의록은 회의 한 건을 잘 남기는 데서 멈추지만, MeetFlow는 **회의가 쌓일수록 프로젝트 흐름이 더 선명해지는 것**을 목표로 합니다.

지난 회의에서 정한 업무가 이번 회의에서 어떻게 됐는지, 아무도 말하지 않은 채 넘어간 건 없는지 —
회의를 이어 붙여야 보이는 것들을 대신 붙잡아 줍니다.

---

## 무엇을 할 수 있나

### 프로젝트 시작
- 구글 로그인, 프로젝트 여러 개를 만들고 오가며 관리
- **6자리 초대 코드**로 팀원 참여
- 팀 프로젝트 / 공모전 / 동아리 — 트랙별로 다른 흐름
- **AI 온보딩** — 목표·기간·인원을 넣으면 마일스톤과 역할 분담 초안을 만들어 줍니다.
  공모전은 요강 PDF를 올리면 텍스트를 뽑아 참고합니다.

### 회의 분석 — 제품의 중심
회의록 텍스트를 넣으면 AI가 이렇게 쪼개서 돌려줍니다.

| 항목 | 내용 |
|---|---|
| `summary` | 2~3문장 요약 |
| `topics` | 안건별 논의 내용 (회의록 본문) |
| `items` | 이번 회의에서 새로 생긴 업무 — 담당자·마감일까지 |
| `carriedOver` | **지난 회의의 미완료 업무가 이번에 어떻게 됐는지에 대한 판단** |
| `gaps` | 회의에서 짚지 못하고 넘어간 부분 |

`carriedOver`가 이 서비스의 차별점입니다. 회의 한 건만 보면 절대 나올 수 없는 값이고,
회의를 이어서 본다는 말이 코드에서 실제로 무엇인지에 해당합니다.

추출된 담당자·마감일·업무명은 화면에서 바로 눌러 고칠 수 있습니다.

### 음성 회의록
- 브라우저에서 바로 녹음하거나, 가지고 있는 오디오 파일을 업로드
- Gemini가 전사해 분석까지 이어집니다 (화자 구분은 없음, 약 43분까지)

### 대시보드 — 7개 화면
개요 · Action Items · 담당자별 · **Task Flow(업무 의존 관계)** · 회의 타임라인 · 회의 브리핑 · 마일스톤

업무 상태는 미시작 → 진행중 → 완료 3단계로 토글하고, 우선순위 분포와 지연 경고를 함께 봅니다.
해시 라우팅이라 **브라우저 뒤로가기가 그대로 동작**합니다.

### 회의 타임라인과 회의록
회의를 시간순으로 쌓아 보여주고, 각 회의의 정식 회의록 문서를 열어볼 수 있습니다.
인쇄하거나 Word 파일로 저장합니다.

### 추가 자료 찾기
회의에서 **못 정하고 넘어간 것들을 검색어로 바꿔** Google 검색으로 실제 웹 자료를 찾아옵니다.
출처 링크와 검색 제안을 함께 표시합니다.

### 프로젝트 마무리 회고
- **팀 회고** — 사람별 역할과 기여, 배운 점
- **개인 심화 회고** — 참여자를 누르면 그 사람만 깊게 팝니다.
  회차별 타임라인, 상황·행동·결과 형식의 하이라이트, 습득한 스킬,
  그리고 **자기소개서에 그대로 쓸 수 있는 문단**까지.
  근거가 되는 본인 업무가 2건 미만이면 결과가 짧을 수 있다고 미리 알려주고,
  없는 내용을 지어내지 않도록 만들었습니다.
- Word 파일로 저장

### 구글 연동
- 업무 마감일 → **구글 캘린더** 일정 등록
- 회의록 → **구글 문서(Docs)**로 내보내기

## 기술 스택

**프론트엔드**
- 빌드 도구 없는 순수 웹 — HTML + CSS + 바닐라 JavaScript (프레임워크·번들러 없음)
- SPA + 해시 라우팅 (`#dash/timeline`), `popstate`로 뒤로가기 지원
- CSS 디자인 토큰으로 색·타이포·간격·반경을 한 곳에서 관리

**백엔드 — 서버를 두지 않았습니다**
- **Firebase Authentication** — 구글 소셜 로그인
- **Cloud Firestore** — `projects/{id}` + 하위 컬렉션 `meetings/{id}`
- **Firestore Security Rules** — 서버 코드 없이 DB 자체에 권한을 선언
- **Firebase AI Logic** — API 키를 클라이언트에 노출하지 않고 Gemini를 호출
- **GitHub Pages** — 정적 호스팅

**AI — Google Gemini (gemini-3.6-flash)**
- 구조화 JSON 출력(`responseSchema`) — 회의 분석·온보딩·회고
- 멀티모달 오디오 입력 — 음성 전사
- **Google 검색 그라운딩** — 실시간 웹 검색 기반 자료 조사

**외부 API**
- Google Calendar API · Google Docs API
- PDF.js — 브라우저에서 PDF 텍스트 추출
- MediaRecorder API — 브라우저 내장 녹음

## 설계에서 고민한 것들

**서버 없이 구글 API를 쓰는 법**
Firebase 구글 로그인에 스코프를 추가하면 액세스 토큰을 받을 수 있고,
그 토큰으로 브라우저에서 Google API를 직접 호출합니다. 백엔드가 필요 없습니다.

```js
provider.addScope('https://www.googleapis.com/auth/calendar.events');
const token = GoogleAuthProvider.credentialFromResult(result).accessToken;
```

토큰은 약 1시간 뒤 만료되고 자동 갱신되지 않아, 만료되면 재로그인을 유도합니다.

**접근 제어를 DB 규칙으로**
프로젝트는 `memberUids` 배열에 든 사람만 읽습니다. 초대 코드로 참여할 때는
*자기 uid 하나만 늘렸는지*를 규칙에서 검사해, 남의 프로젝트에 끼어들거나
다른 멤버를 지우는 걸 막습니다.

아직 멤버가 아닌 사람은 프로젝트 본문을 읽을 수 없으므로,
코드로 프로젝트를 찾을 수 있게 `invites/{code}` 컬렉션을 공개 인덱스로 따로 뒀습니다.

**AI 호출을 용도별로 분리**
검색 그라운딩을 구조화 JSON과 함께 쓰면 출처 정보가 비어서 돌아옵니다.
그래서 회의 분석(JSON)과 자료 찾기(그라운딩)를 **별도 호출로 유지**합니다.
그라운딩 응답은 Google 정책상 검색 제안과 출처를 화면에 표시해야 합니다.

**결과를 저장해 다시 부르지 않기**
회고와 자료 조사 결과는 Firestore에 저장해, 다시 열 때 AI를 재호출하지 않습니다.

## 구조

```
index.html      마크업 + Firebase/Gemini 호출구(맨 아래 module 스크립트)
css/            base(디자인 토큰) · app(제품 화면) · landing
js/             기능별 15개 파일
firestore.rules 접근 제어 규칙
```

| 파일 | 역할 |
|---|---|
| `js/state.js` | 전역 상태·상수 |
| `js/utils.js` | 토스트 등 유틸 |
| `js/auth.js` | 구글 로그인 |
| `js/router.js` | 해시 라우팅, 페이지·탭 전환 |
| `js/projects.js` | 프로젝트 CRUD, 초대 코드 |
| `js/onboarding.js` | 트랙별 AI 온보딩 |
| `js/gemini.js` | Gemini 공통 호출·프롬프트·스키마 |
| `js/stt.js` | 녹음 + 전사 |
| `js/meetings.js` | 회의 분석, 이월 업무 반영, 이력 저장 |
| `js/dashboard.js` | 대시보드 렌더링 |
| `js/timeline.js` | 회의 타임라인·회의록 문서 |
| `js/research.js` | 검색 그라운딩 자료 찾기 |
| `js/wrapup.js` | 팀·개인 회고 |
| `js/google.js` | 캘린더 등록, Docs 내보내기 |
| `js/main.js` | 시작점 |

⚠️ `js/`의 스크립트는 **일반 스크립트**입니다 (`type="module"` 아님).
마크업에 `onclick="gp('upload')"` 같은 인라인 핸들러가 60개 넘게 있어 전역 스코프가 유지돼야 합니다.
**모듈로 바꾸면 전부 깨집니다.** `index.html`의 스크립트 로드 **순서도 의존성**입니다 —
상태·유틸이 먼저, `main.js`가 마지막입니다.

## 실행 방법

```bash
python -m http.server 8000
```

http://localhost:8000 으로 접속합니다. `localhost`는 Firebase 승인 도메인이라 구글 로그인이 바로 됩니다.
`index.html`을 더블클릭해 `file://`로 열면 **로그인이 동작하지 않습니다.**

> 코드를 고쳤는데 화면이 그대로면 브라우저 캐시입니다. `Ctrl+Shift+R`로 강력 새로고침하세요.

Firestore 규칙을 바꿨다면 배포해야 반영됩니다.

```bash
firebase deploy --only firestore:rules
```

## 알려진 한계

- **데스크톱 전용입니다.** 모바일·반응형은 하지 않기로 했습니다.
  미디어쿼리가 없고 일부 레이아웃이 고정폭인 것은 의도된 상태입니다.
- 음성 전사에 **화자 구분이 없습니다.** 내장 녹음은 48kbps·15MB 상한이라 약 43분까지입니다.
- AI 호출이 `401 App Check token is invalid`로 막힐 수 있습니다. 콘솔 설정 문제입니다.
- `functions/`, `storage.rules`는 Cloud Speech-to-Text(화자 분리)용으로 만들었으나
  **현재 사용하지 않습니다.** 화자 분리는 서비스 계정 인증이 필요해 브라우저에서 직접
  호출할 수 없고 Cloud Function + Blaze 요금제가 있어야 해서, Gemini 전사만 쓰기로 했습니다.
